    4.1.3
        - UX: "Configure Azure Maps Key…" moved from the top-level
          TMS for Korea menu into the Azure Maps submenu so the key

        - UX: Azure Maps layer entries (Road / Satellite / Hybrid) are

    4.1.2
        - Hotfix: "Configure Azure Maps Key…" menu action raised
          AttributeError: type object 'QLineEdit' has no attribute
          'Normal' under PyQt6. Replaced Qt5-style short alias
          QLineEdit.Normal with the fully-qualified spelling
          QLineEdit.EchoMode.Normal so the key-entry dialog opens
          successfully on QGIS 4.x.
    4.1.1
        - Fix: Naver tile requests now succeed under QGIS 4. Naver's CDN
          (map.pstatic.net) returns HTTP 500 whenever the User-Agent
          header matches `Mozilla/5.0 QGIS/<digit>` — which is QGIS's
          default UA shape — so every tile request from QGIS 4 was
          rejected upstream regardless of URL correctness. The plugin
          now registers a QgsNetworkAccessManager request preprocessor
          that rewrites the UA to a generic desktop browser string for
          requests to map.pstatic.net only; all other traffic is left
          untouched. Verified 2026-05-15 via curl:
            HTTP 500  UA="Mozilla/5.0 QGIS/4.0.1"   (default — blocked)
            HTTP 200  UA="Mozilla/5.0 (Windows ...) Chrome/120..."
        - The preprocessor is registered in initGui and removed in
          unload, so disabling the plugin restores the global default.
    4.1.0
        - Add: Azure Maps (Road, Satellite, Hybrid) via the official
          v2024-04-01 tile API. Requires a user-supplied subscription
          key — configure via "Web > TMS for Korea > Configure Azure
          Maps Key...". Free S0 tier covers casual map browsing
          (azure.microsoft.com/products/azure-maps).
        - Add: when an Azure layer is requested without a key configured,
          the menu action shows a message-bar hint instead of attempting
          an inevitable 401 response.
        - The Azure subscription key is read on each layer-add from
          QSettings, so a key entered after plugin load takes effect
          without restarting QGIS.
        - URL builder verified to round-trip multi-parameter URLs
          (Azure has 5 inner '&' chars) through QGIS's xyz URI parser.
    4.0.1
        - Fix: Naver tile URIs not rendering on QGIS 4. Previous build
          aggressively percent-encoded the URL template (?, &, =, @ etc.)
          inside the XYZ URI; some QGIS 4 builds did not decode it back
          before substituting {z}/{x}/{y}, producing malformed tile
          requests. URI now mirrors QGIS's own xyz-connection dialog
          format (type=xyz first, raw URL template, only '&' encoded).
        - Add: Naver Cadastral layer is now registered (was deferred
          from 4.0.0 release scope).
        - Add: every TMS layer-add is now logged to "Log Messages >
          TMS for Korea" with the URL template, full URI, and validity
          status. Invalid layers also push a message-bar warning.
        - Phase 2 research: Kakao, Google, Bing all deferred indefinitely
          due to upstream policy (Kakao tile API blocked since 2025-10-20,
          Google Maps ToS requires session-token API + billing, Bing Maps
          for Enterprise closed to new keys since 2024-06-30). See
          MIGRATION.md for full notes.
    4.0.0
        - First stable release for QGIS 4.x (Qt6). Verified loading and
          tile rendering on QGIS 4.0.1 (Norrkoping).
        - Working layers: VWorld (Street/Gray/Satellite/Hybrid), Naver v5
          (Street/Hybrid/Satellite/Physical) via XYZ tiles with dynamic
          version-token discovery, OpenStreetMap Standard.
        - Removed legacy QtWebKit-based renderer and OpenLayers Overview
          dock (Qt6 has no QtWebKit).
        - Hardened readXml so legacy 3.x projects containing Kakao/NGII
          layers degrade gracefully instead of crashing.
        - About dialog uses lazy construction and Qt6-compatible enum
          spellings; pyrcc/pyuic generated files migrated to qgis.PyQt.
        - Kakao, NGII, Mango deferred to a future release (4.1+);
          Kakao/NGII require GDAL TMS minidriver work for their
          custom CRS tile schemes, Mango upstream is unreachable.
